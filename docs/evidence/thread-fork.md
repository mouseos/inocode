# スレッドの途中からのフォーク

- **対象と範囲：**
  - 要求 `thread/fork {thread_id, before?, through?}`：スレッドを写した新しいスレッドを作り、`{thread_id, from}` を返す。
    - 何も付けなければ、全部を写す。
    - `before`：人のメッセージの番号（`seq`）を付けると、そのメッセージの手前までを写す。そのメッセージを書き直して別の道を試すため。
    - `through`：人のメッセージの番号を付けると、そのメッセージと、人の次のメッセージまでに続いたもの（返事、道具の呼び出しと結果）を写す。
    - 両方は付けられない。番号が人のメッセージでなければ `invalid_params`。
    - 切った位置のすぐ前に、写さないメッセージに付いた返信の引用（`reply` の種類の inocode のメッセージ）があれば、それも写さない。
    - 計画、約束、モデルの選択は、今のものを写す。目標は写さない（`/fork` と同じ）。
    - ターンが走っている間は `turn_running` で断る。走っているターンのメッセージは、まだ全部は保存されていないため。
  - 範囲外：
    - スラッシュコマンド `/fork` は今のまま（全部を写す）。
    - フォークの作成を画面に知らせる通知は `thread-operations.md`（`thread_created` の `from`）。
  - 限界：`through` の「人の次のメッセージ」には、ターンの途中で `turn/steer` で足したメッセージも入る。その場合は、ターンの途中で切れる。
- **関連ソースコード：**
  - `core/src/lib.rs`：`ForkCut`、`fork_end`、`Core::fork_thread`。
  - `core/src/store_threads.rs`：`fork_session_through`。
  - `core/src/turn.rs`：`REPLY_KIND`（crate の中に公開）。
  - `server/src/lib.rs`：`fork_thread`。
  - テスト：`server/tests/turn_tcp.rs` の `a_thread_forks_before_or_through_a_message_of_the_person`。

## 検証

- 上のテストで確かめたこと：
  - 2 つ目の人のメッセージの手前で切ると、1 つ目のターンだけが残り、返信の引用は入らない。
  - 1 つ目の人のメッセージで `through` を付けても、同じ結果になる。
  - 2 つ目のメッセージで `through` を付けると、全部が残る。1 つ目のメッセージの手前で切ると、人のメッセージは何も残らない。
  - フォークしたスレッドでターンを続けると、モデルに送る履歴に、切り捨てた発言が入らない。
  - 人のメッセージでない番号、`before` と `through` の両方、無いスレッドは断られる。
- 確かめていないこと：ターンの途中で足したメッセージで `through` を付けたとき。
