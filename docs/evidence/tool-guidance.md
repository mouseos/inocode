# システムプロンプトのツールの使い分け

- **対象と範囲：** システムプロンプトに、inocode 自身のツールの使い分けを短く書く（`core/src/turn.rs` の `TOOL_GUIDE`）。各ツールが何をするかと引数は、これまでどおり各ツールの説明（ツール定義）に書く。MCP のツールは、名前の形だけを書く。
- **関連コード：** `core/src/turn.rs`（`TOOL_GUIDE`、`system_prompt`）。ツールの説明は各モジュールの `spec`・`specs`。
- **根拠の状態：**
  - ツールの説明を詳しく・明確にすると、ツールの使い方が良くなる：RESEARCH_SUPPORTED（下の 1〜3、査読あり 2 件）。
  - 説明をシステムプロンプトに置くこと：UNSUPPORTED_APPROVED。システムプロンプトとツールの説明の置き場所を、ツールの呼び出しで比べた研究は見つからなかった。ユーザーの指示による。
- **ユーザーの判断：** 2026-11-20「各種ツールだがモデルが知らない可能性あるので指示はシステムプロンプトに入れたほうがいい」。

## 研究（2026-11-20、サブエージェントが全文を読み、報告）

1. Hsieh ほか, "Tool Documentation Enables Zero-Shot Tool-Usage with Large Language Models", arXiv 2308.00675（査読は未確認）：説明だけで、例示 12〜16 個と同等以上。架空の CLI ツールで、gpt-3.5-turbo の F1 は説明なし 0.13、説明あり 0.45（4.2 節、図 5）。説明は約 600 語までは長いほど良く、それを超えると下がった（図 7）。
2. EasyTool（Yuan ほか、NAACL 2025）：長い説明を、何をするかと使い方の指針の短い形に書き直すと、ToolBench の成功率が ChatGPT で 15.0 → 52.8（表 4）。トークンは 70.43% 減（表 3）。
3. DRAFT（Qu ほか、ICLR 2025）：試行から説明を書き直すと、GPT-4o で TMDB 71 → 88 など（表 1）。書き直しを重ねすぎると冗長になり悪化した（図 6）。
4. "MCP Tool Descriptions Are Smelly!"（Hasan ほか、arXiv 2602.14878、査読前）：説明に「いつ・どう使うか」（Guidelines）を含めて直すと、成功率が中央値で +5.85 ポイント。ただし手順は +67.46%、入力トークンは +21.85〜41.43%、16.67% の組み合わせで悪化。
5. Faghih ほか, "Tool Preferences in Agentic LLMs are Unreliable"（arXiv 2505.18135、査読前）：「最も効果的な」のような強い言い方を足すと、同じ働きのツールの選ばれる割合が 7 倍を超えた。説明を長くするだけではほぼ変わらない。
6. 置き場所：Lin, "Your Prompt Is Not the Only Prompt"（arXiv 2608.08254、査読前、個人の研究者）。ツールの呼び出しではなく、構造化出力の分類。定義をシステムプロンプトに置くと、スキーマの説明に置くより同じか良い（GPT-4.1 で 89.6 対 77.1、Claude Sonnet 4.6 で 83.8 対 82.9）。2 か所の定義が食い違うと 5〜45 ポイント下がった。48 問だけ。

## 各社の推奨とほかのハーネス（研究ではない）

- Anthropic の文書：ツールの説明を非常に詳しく（何をするか、いつ使うか・使わないか、引数、注意点）。Claude では、ツールの定義も API がシステムプロンプトに組み込む。
- OpenAI の GPT-4.1 の手引き：ツールの説明は tools 欄に置く（プロンプトに書くより SWE-bench Verified で +2%）。複雑なツールの例はシステムプロンプトの例の節に。GPT-5 の手引き：強い言い方（「徹底的に」）が検索のツールの使いすぎを招いた例。
- Codex CLI：システムプロンプトに「Tool Guidelines」の節がある（シェル、apply_patch、計画）。
- OpenCode：有効なツールについてだけ、いつ使うかの短い行をシステムプロンプトに入れる。ツールの説明は別。
- Claude Code：ツールの説明とは別に、システムプロンプトにツールの使い方の節がある（文面はここには載せない）。

## 実装

- ツールごとに 1 行か 2 行で、何に向くか・ほかのツールとどう使い分けるかを書いた。引数は書かない（ツールの説明にある）。
- 強い言い方（「必ず」「最も効果的な」）は使わない（5、GPT-5 の手引き）。
- 各ツールの説明と食い違わないように、説明を言い換えた文にし、新しい規則は足していない（6）。
- システムプロンプトの最初の説明の直後、返答の言語とプロジェクトの規則の前に置く。毎回同じ文なので、キャッシュは崩れない。
- 長さは約 150 語（1 の 600 語より十分短い）。

## 検証

- 単体テスト `the_tool_guide_names_every_tool_of_the_harness`：ツールの一覧（サンドボックスの有無の両方）のすべての名前がこの節にあること。ツールを足したのに節を直し忘れると失敗する。
- 未検証：実際のモデルでツールの選び方が良くなるか（ベンチマークは完成後）。
