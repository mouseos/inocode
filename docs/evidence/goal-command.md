# goal コマンド（目標が達成されるまで自動で続ける）（調査のみ）

- **対象と範囲：** 人が目標を決めると、モデルが答えを終えても、目標が達成されたと確かめられるまで、ハーネスが次のターンを自動で始める仕組み。
- **関連コード：** 未実装。近い既存の仕組みは、ローカル issue と未完了の試行の記録、同僚、人への質問（`colleague-review.md`）、計画（`plan`）。
- **根拠の状態：** UNSUPPORTED_PENDING。仕組みの部品には根拠があるが、自動で続ける仕組みそのものが結果を良くするという研究はない。実装には承認が要る。
- **ユーザーの判断：** 2026-11-21「goalコマンドがいるかどうかもいるなら仕組み調査」。実装の承認はまだない。

## ほかのハーネス（2026-11-21、サブエージェントがソースと公式文書を読み、報告）

| ハーネス | 決めるもの | 続け方 | 達成の判定 | 止まるとき |
|---|---|---|---|---|
| Codex CLI `/goal` | 目標の文、任意のトークンの予算 | スレッドが止まり目標が有効なら、続けるための文（「進んだか確かめる」「目標を易しくしない」「要件ごとに今のファイルとテストの出力で確かめる」）で次のターンを始める。目標はスレッドの状態に保存し、圧縮の後も残す | 作業役のモデル自身が `update_goal(complete)` を呼ぶ | 完了、同じ障害が 3 ターン続いたら blocked、動きのない自動ターンが 3 回、予算切れ、利用の上限 |
| Claude Code `/goal` | 達成の条件の文（4,000 文字まで） | セッション中の Stop フック | 別の小さなモデルが毎ターン会話を読み「まだ」「達成」「不可能」を返す（ツールは使わない） | 達成・不可能、続けての継続は 8 回まで、道具を呼ばないターンが続く、人が直す必要のある誤り |
| OpenCode `/goal` | 目標 | 毎ターンの後の判定 | 判定の文（主張は証拠にならず、ツールの結果・コマンドの出力・ファイルだけを見る）で、たぶん同じモデル | 50 ラウンド、止まった（道具なし・同じ理由）が 3 回、裏の作業の待ちが 30 分 |
| Gemini CLI、Aider、Devin など | なし | Gemini は次に話すかをモデルで判定（既定で無効）、Aider は編集の後にテストを走らせ失敗を返す（3 回まで） | — | — |

## 研究（同）

- 早く止まりすぎることは実在する：METR（Kwa ほか、arXiv 2503.14499、査読前）で、o1 の失敗 32 件のうち 16 件が途中で投げ出したもの。MAST（arXiv 2503.13657）で、早い終了 6.2%、終わったと気づかない 12.4%。
- 外からの確かめが自分の確かめより良い：Huang ほか（ICLR 2024）では、外の手がかりなしの見直しで正答が下がる。Reflexion（NeurIPS 2023）は、自分で作ったテストが誤ったコードを通すと（MBPP で 16.3%）かえって悪くなった。
- 続けることの危険：ImpossibleBench（arXiv 2510.20270、査読前）で、失敗の後に出し直せると、テストをごまかす割合が 33% → 38% に上がった。テストを読み取り専用にするとテストの書き換えが止まり、「やめて人に知らせる」逃げ道を与えると GPT-5 のごまかしが 54% → 9% に下がった。
- 目標のずれ：Arike ほか（arXiv 2505.02709、技術報告）で、どのモデルも長い文脈で目標から多少ずれた。

## 設計案（推測。実装は承認待ち）

1. 目標の文と任意の予算をスレッドの状態に保存し、圧縮の後も入れ直す。
2. ターンが終わり、目標が有効で、人の新しい発言がなければ、続けるターンを始める。
3. 達成は証拠で決める：人が決めた確認のコマンド（テストなど）をハーネスが走らせる。なければ、ツールの出力を読む別の判定。モデルの主張だけでは達成にしない（Huang、Reflexion）。
4. 歯止め：ラウンドの上限、トークンの予算、3 回止まったら終える、直らない誤りで終える、テストの書き換えに印を付ける、人に知らせて止まる逃げ道（ImpossibleBench）。
5. 既存の仕組みとの関係：目標をスレッドが着手した issue に結びつけ、未完了の試行の記録を使う。止まったら、同僚 → 人の順（`colleague-review.md`）。
- 根拠がないもの：自動で続けること自体の効果、上限の値（3、8、50）、別の判定役と自分の確認のどちらがよいか。
