# 特定のメッセージへの返信

- **対象と範囲：** 人が、スレッドの前のメッセージを指定して返信できるようにする（チャットの「返信・引用」）。内部ではメッセージの ID（保存の位置 `seq`）で指定する。モデルに、新しい入力がどのメッセージについてのものかを正確に伝えるのが目的。
- **関連コード：** `core/src/turn.rs`（`Prompt`、`quote`、`steps` の始め）、`core/src/lib.rs`（`Request::reply_to`、`Core::run_turn`）、`server/src/lib.rs`（`turn/start`）。続きを読むのは既存の `recall`（`core/src/agent_tools.rs`）。
- **根拠の状態：** UNSUPPORTED_APPROVED。返信の機能を直接評価した研究は見つからなかった。間接的な研究だけ（下）。
- **ユーザーの判断：** 2026-11-20「特定のメッセージを内部的にはIDで指定して返信できる機能が欲しい。これも調べておいて」。同日、調査の報告の後に「返信はよほどトークン増えるとかじゃない限り実装して」。

## 研究（2026-11-20、サブエージェントが全文を読み、報告）

- Laban ほか, "LLMs Get Lost In Multi-Turn Conversation", arXiv 2505.06120（査読前）。
  - 課題を複数のターンに分けると、6 課題・15 モデルの平均で成績が 39% 下がる。
  - 途中のターンが失われやすい：8 ターン目の要約が引用したのは、8 ターン目に与えた文書が 20%、2〜3 ターン目のものが 8%（付録 F.3、図 10）。
  - 前の発言を最後に繰り返すと一部回復する（7.1 節、表 2）。GPT-4o で、1 回で全部渡すと 93.0、分けると 59.1、最後にまとめて繰り返すと 76.6。
  - 限界：模擬のユーザー、英語だけ。繰り返したのはすべての前の発言で、選んだ 1 つではない。
- MT-Eval（Kwan ほか、EMNLP 2024）：前の指示から離れるほど守らなくなる（GPT-4 以外）。文書と質問のあいだに無関係なターンを挟むと点が下がる（Qwen-chat-14B 6.30 → 5.17。表 6）。GPT-4 は下がらない（7.79 → 7.97）。
- MT-Bench-101（Bai ほか、ACL 2024）：短い会話（1 会話あたり約 3 ターン）では、代名詞が何を指すかの課題の平均は 8.26／10（GPT-4 は 9.58）。短い会話では、返信の機能の必要は小さい。
- Lost in the Middle（Liu ほか、TACL）：必要な情報が真ん中にあると最も悪く、先頭か末尾だとよい。会話のターンではなく、1 回の入力の文書での結果。
- Tan ほか, "Is ChatGPT a Good Multi-Party Conversation Solver?"（Findings of EMNLP 2023）：返信先を「Reply to #ID — 引用の文」の形で入れると、GPT-4 は良くなり（話し手の特定 +11.50%）、ChatGPT は悪くなった（−25.18%）。強いモデルは構造を使え、弱いモデルは混乱する、と著者は解釈。
- 引用とID だけを直接比べた研究は見つからなかった。

## 実装

- プロトコル：`turn/start` の `params` に `reply_to`（返信先のメッセージの `seq`。`thread/read` が返す番号）を足せる。省略か `null` なら返信なし。整数でなければ `invalid_params`。スレッドにその番号がなければ、ターンは `invalid_params`（「the thread has no message N to reply to」）で失敗し、人の発言も保存しない。
- 引用：保存された原文から作る（圧縮で要約された後でも原文）。人の発言の直前に、ハーネスの発言（種類 `reply`）として次の形で入れ、履歴にも保存する。
  - `The person's next message replies to message {seq}, written by {書き手}:` の後に、各行に `> ` を付けた原文。
  - 書き手：人の発言は the person、モデルの発言は you（文の部分だけ。考えの過程と道具の呼び出しは除く）、道具の結果は the tool {名前}、ハーネスの発言は the harness。
  - 2,000 文字まで。超えたら切り、`(quoted up to here; recall with from_seq {seq} reads it whole)` と足す。
- トークン：返信 1 回で増えるのは、引用（最大 2,000 文字）と前置きの 1 行だけ。引用は履歴に残るので、以後のターンでも送られる（圧縮の対象にはなる）。ユーザーの条件「よほどトークン増えるとかじゃない限り」に対して、上限で抑えた（上限の値は工学上の選択）。
- 研究との対応（推測による当てはめ）：返信先を新しい発言の近くに置くこと（Laban ほか、Lost in the Middle）、ID と引用の文を両方渡すこと（Tan ほか、ほかのツール）。

## 検証

- 結合テスト（`server/tests/turn_tcp.rs` の `a_reply_quotes_the_message_it_replies_to`、模擬 API）：モデルの発言への返信で、引用が人の発言の直前に入ること。長い発言は 2,000 文字で切られ、`recall` の案内が付くこと。ない番号と整数でない値で、ターンが失敗すること。
- 未検証：実際のモデルが引用を返信先として正しく読むか（ベンチマークは完成後）。
- 未対応：ターンの途中の追加の発言（`turn/steer`）からの返信。
