# 返答の言語（調査のみ）

- **対象と範囲：** モデルが人に返す文の言語を、inocode がどう決めて指示するか。人が明示した場合と、明示していない場合の両方。
  - 避けたい挙動（ユーザーの報告、2026-11-20）：Muse Code のハーネスは、いちど返答の言語を英語や韓国語に決めると、人が日本語で書き、日本語で話すよう求めても、その言語のまま変わらない。この仕組みはまねしない。
- **関連コード：** 未実装。いまの inocode のシステムプロンプト（`core/src/turn.rs` の `system_prompt`）には、言語についての指示がない。
- **根拠の状態：** UNSUPPORTED_PENDING。
  - 言語の指示を入れると誤った言語の応答が減ること、指示をプロンプトの途中に埋めると悪いことは、査読ありで確認（下の A1）。ただし 1 ターンだけの実験。
  - 英語の文脈（取得した文書）が英語への切り替わりを招くことは、査読ありで確認（A2）。ただし RAG の実験で、エージェントのツール出力ではない。
  - 長い会話・エージェントの文脈での切り替わり、毎ターンや末尾での指示の繰り返しの効果、最新の発言から言語を判定する方式の評価：研究なし。
- **ユーザーの判断：** 2026-11-20「inocodeに返答文書の言語設定をしないといけない」「ユーザーからの明示がない場合の返答言語…を調べて」。実装の承認はまだない。

## 研究（2026-11-20、サブエージェントが原文を読み、数値を報告）

### A1. Marchisio ほか, "Understanding and Mitigating Language Confusion in LLMs", EMNLP 2024（査読あり）

- arXiv 2406.20052、https://aclanthology.org/2024.emnlp-main.380 。15 言語。monolingual（その言語で書き、その言語の返答を期待）2,600 件、cross-lingual（英語で書き、別の言語での返答を指示）4,500 件。
- LPR（誤った言語の行が 1 行もない応答の割合）：GPT-4o は mono 98.9、cross 92.4。GPT-4 Turbo は 99.3、90.3。Llama 3 70B-Instruct は 46.0、30.3。強いモデルでも、英語で書いて別の言語を指示すると約 1 割を誤る。
- 英語中心の調整が混乱を生む例：Llama 2 70B の monolingual LPR（ar/hi/ja/ko/vi/zh 平均）は、基のモデル 98.5、指示調整後 6.0。
- 指示の位置（cross-lingual LPR、先頭／途中／末尾）：Command R 86.7／69.0／85.1、Command R+ 94.4／90.3／95.2、GPT-4 93.0／91.7／95.0。途中に埋めると最も悪く、末尾は先頭と同じかよい。
- 温度が高いほど語の混入が増える（Command R：T=0 で WPR 97.2、T=1.0 で 86.5 か 83.5。本文と表で食い違う）。
- 限界：system メッセージでの指示は調べていない。1 ターンだけで、複数ターンは今後の課題と明記。最大 100 トークンの生成。

### A2. 英語の文脈による切り替わり

- Li・Xu・Xie, "Language Drift in Multilingual RAG", AAAI 2026（arXiv 2511.09984）。中国語の質問に英語の文書を添えると、返答の言語の一貫性が下がる（LLaMA3-8B、HotpotQA：0.981 → 0.883、例示ありで 0.920 → 0.684）。英語が最も強く引き込む。対象言語で答えるよう指示しても、中英の組で 68.4% にとどまった。デコードを変える手法（SCD）で 90.6%。
- 査読前：Zhan ほか（arXiv 2605.27649）は、劣化を最も左右するのは「返答に求める言語」が他と違うこと（一貫性：全部一致 .975、返答の言語だけ違う .860）。BabelArena（arXiv 2609.23490、要旨のみ）は、切り替わりは圧倒的に英語へ向かうと報告。Multi-IF（arXiv 2410.15553）は、ターンが進むほど指示を守らなくなる（言語に限らない）。
- 当てはめ（推測）：コーディング作業の文脈はツール出力・コード・英語の文書で大半が英語なので、指示を先頭に 1 回書くだけでは英語に戻りやすい。

### A3. どの発言から言語を決めるか

- 3 つの方式（最新の発言、最初の発言、固定の設定）を比べた研究は見つからなかった。
- Widdows・Brew（arXiv 2109.09862、査読は未確認）：顧客チャット 5 万会話で、1 つの発言の言語判定が会話全体の判定と違ったのは 12〜14%。「No」のような短い発言は単独では言語が決められない。
- 推測：最新の発言だけで決めると短い発言で誤る。最初の発言で固定すると、Muse Code と同じ固定の問題になる。

## 設計案（推測。実装は承認待ち）

1. 人が明示したら、それに従う（設定、またはターンの中の「日本語で」などの指示）。会話の途中の明示は、以前の決定より常に優先する。いちど決めた言語を固定して、人の指示より優先することはしない（Muse Code の問題の回避）。
2. 明示がないときは、人の最近の発言の言語に合わせる。短い発言では決めず、それまでの判定を使う。
3. 指示はシステムプロンプトの先頭近くと、会話の末尾（毎回の要求の最後、作業状態を入れている位置）の両方に置く。途中に埋めない（A1）。末尾に置くとキャッシュを崩さない。
4. 圧縮の要約にも返答の言語を残す。
- 未解決の論点：言語判定の方法（依存を増やすか、文字の種類で簡単に判定するか）、設定の置き場所、ツールの合間の短い説明文にも効くか。
