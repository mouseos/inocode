# Anthropic のプロンプトキャッシュ

- **対象と範囲：** Anthropic Messages 形式の要求に、プロンプトキャッシュの区切り（`cache_control: {"type": "ephemeral"}`、5 分の保持）を付ける。区切りは 2 か所：
  - system の最後のブロック（ツール定義と system をまとめて保存する）
  - 会話の最後のブロック。ただし要求ごとに付けて外す状態（計画・教訓）のメッセージは除き、その手前に付ける
  - 範囲外：OpenAI 形式・Responses 形式（それぞれの API は自動でキャッシュする）、1 時間の保持、事前の温め、ほかの区切り位置
- **関連コード：** `core/src/conversation.rs`（`to_anthropic`、`STATE`）、`core/src/llm.rs`（Claude OAuth で system の先頭に識別ブロックを足す処理）、`core/src/turn.rs`（状態のメッセージ）。
- **根拠の状態：** UNSUPPORTED_APPROVED。効果の根拠は学術研究ではなく、提供元の公式仕様と料金。

## 公式仕様（学術研究ではない）

- Anthropic のプロンプトキャッシュの説明（Claude API のスキルに同梱された `shared/prompt-caching.md`、2026-11 時点で確認）：
  - キャッシュは区切りまでの要求の内容（ツール → system → messages の順）と完全に一致したときだけ読まれる。1 バイトでも変われば、それ以降は読まれない。
  - 1 要求の区切りは 4 つまで。
  - 保存の最小の長さはモデルごとに異なる。Claude Haiku 5.5 などは 512 トークン。
  - 料金：
    - 読み込みは通常の入力の約 0.1 倍（Opus 5.5・Sonnet 5.5 は 0.05 倍）。
    - 5 分保持の書き込みは 1.25 倍。
  - Claude API では、キャッシュの読み込みは多くのモデルで入力トークンのレート制限に数えられない。
  - 区切りは、前の要求が書いた位置から 20 ブロック以内にないと見つからない。
- 要求ごとに付けて外す状態のメッセージに区切りを付けると、次の要求ではその位置が存在しないため読まれない。そのため状態の手前に付けた。

## 限界・未確認

- Claude のサブスクリプション（OAuth）の使用量に、キャッシュの読み込みがどう数えられるかは確認していない。
- 古いツール出力を隠す処理（`observation-masking.md`）と組み合わせると、隠す位置が変わるたびに、そこから後ろが書き直しになる。
- 区切りに付けたブロックが思考ブロックになる場合は想定していない（要求は常に利用者側のメッセージで終わる）。

## 実装・検証の状況

- テスト：
  - `core/src/conversation.rs` の `anthropic_merges_results_with_the_next_user_turn`：system と最後のブロックに区切りがあり、状態のメッセージが付いたときはその手前に付く。
  - `server/tests/anthropic_tcp.rs`：送られる本文に区切りが含まれる。
- 実 API（Claude OAuth、Claude Haiku 5.5）で読まれたことを確かめた。カーネルの実測（`find-enclosing.md`、キャッシュありの 160 ターン）：
  - 入力の中央値は 18,124（C）、そのうちキャッシュ外は 4,008。
  - キャッシュのない以前の実行（A）では、キャッシュ外は入力と同じ 38,109。
  - キャッシュは応答を待つ時間も短くしうる。そのため、ほかの改良との時間の比較には、キャッシュの影響が混ざる。
