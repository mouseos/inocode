# 操作用のポートの認証と、サンドボックスから設定のフォルダーを隠すこと

- **対象と範囲：** `inocode-server` が 127.0.0.1 で受ける接続すべてに、起動ごとの合言葉（トークン）を求める。サンドボックスの中のシェルの命令から、合言葉と鍵のある `~/.inocode` を読めなくする（OS が許す範囲で）。範囲外：ネットワーク越しの接続（もともと 127.0.0.1 だけ）、TLS、利用者ごとの権限の区別。
- **関連コード：** `server/src/lib.rs`（`authenticate`、最初のフレームの確認）、`server/src/main.rs`（`write_token`、`serve`）、`core/src/sandbox/mod.rs`（`hide`）、`core/src/sandbox/windows.rs`（`hide`、ラベル）、`core/src/sandbox/linux.rs`（bwrap の `--tmpfs`）、`core/src/sandbox/macos.rs`（`profile`）、`server/tests/support/mod.rs`（試験の接続）。
- **根拠の状態：** UNSUPPORTED_APPROVED
- **ユーザーの承認：** 2026-11-25、`docs/known-problems.md` の問題をすべて、深刻なものから直すよう指示（A1「操作用のポートに認証が無い」を含む）。方式（起動ごとの合言葉のファイル＋サンドボックスで隠す＋最初のフレームで確かめる）は、その指示を受けた作業の中で選んだ。

## 守りたいこと

- モデルが動かすシェルの命令（サンドボックスの中）が、127.0.0.1 のポートにつないで、プロバイダの送り先を書き換える、`full` モードでターンを始める、サンドボックスを切る、などをできないようにする。
- 同じ PC の別のユーザーも同じ。

## 方式

1. 起動のたびに 32 バイトの乱数（OS の乱数）から合言葉を作り、`~/.inocode/server-token` に書く。Unix では本人だけが読める権限（0600）で作る。Windows ではユーザーのプロファイルの権限（本人・SYSTEM・Administrators）を引き継ぐ。前の起動の合言葉は上書きで無効になる。
2. 接続の最初のフレームは `{"id": n, "method": "auth", "params": {"token": "<合言葉>"}}` でなければならない。合えば `{"id": n, "result": {"authenticated": true}}` を返し、以後ふつうに要求を受ける。合わない・別の要求・JSON でない・10 秒以内に来ない場合は、`unauthorized` の誤りを返して（返せるとき）接続を閉じる。比較は、どこで食い違ったかで時間が変わらない方法で行う。
3. サンドボックスの中の命令からは `~/.inocode` を読めなくする。命令が書く一時フォルダー（`~/.inocode/inocode.files/logs/thread-N/tmp`）だけは中に入れる。
   - Windows：`~/.inocode` に「中（Medium）の整合性、低い整合性からの読み書きを禁止（no-read-up・no-write-up）、下へ引き継ぐ」のラベルを付ける。サンドボックスの命令は低い（Low）整合性で動くので読めない。一時フォルダーには、それより前に効く Low のラベルが付く（サンドボックスがもともと付けている）。サーバー自身は中の整合性なので読める。フォルダーにラベルを付けても、すでに中にあるファイルやフォルダーには届かない（試験で確かめた）ので、初めて付けるときに中のものにも 1 つずつ付ける。自分のラベルを持つもの（一時フォルダー）とその中は飛ばす。その後に作られるものは、フォルダーのラベルを引き継ぐ。付けたラベルはフォルダーに残る。ラベルを付けるのに `WRITE_OWNER` が要るときは、サンドボックスの書き込みの許可と同じく、本人にそのフォルダーだけの `WRITE_OWNER` を足してから付ける。
   - Linux（bwrap）：`~/.inocode` の上に空の tmpfs をかぶせ、その後で一時フォルダーを結び直す。
   - macOS：Seatbelt のプロファイルで `~/.inocode` の読み取りを禁じ、その後で書き込める 2 つのフォルダーの読み取りを許し直す（後に書いた規則が勝つ）。
4. 起動の前に、同じデータベースを使うサーバーがもう動いていないかを `inocode.db.lock` の OS のロックで確かめ、動いていれば起動しない。

## 残る危険（正直に）

- Linux で bwrap が使えず Landlock で閉じ込めるとき、命令は `~/.inocode` を読める。Landlock は「許す場所を並べる」方式で、一部だけを隠すには、ほかの場所を全部並べなければならず、現実的でない。この場合、サンドボックスの中の命令は合言葉を読んで接続できる。
- `full` モード、`--sandbox off`、設定の `server.sandbox: false` では命令は閉じ込められず、合言葉を読める。
- MCP のサーバー（stdio）やプラグインの命令は、サンドボックスの外で動くので読める。
- 同じユーザーのほかのプログラム（サンドボックスの外）は合言葉を読める。合言葉は「同じユーザーの、閉じ込められていないプログラム」を区別しない。
- macOS の規則は CI（macos-latest）では試していない（この作業の環境は Windows）。Linux の bwrap の経路も未検証（このマシンでは動かしていない）。
- Windows のラベルは、ほかの Low 整合性のプログラム（ブラウザのサンドボックスなど）も `~/.inocode` から締め出す。これは望ましい向き。
- 合言葉はファイルにそのまま書く。暗号化はしない（読める人は、もともと同じユーザーの権限を持つ）。

## 学術的な主張・不足点

- 適用可能な学術研究は確認できていない。ローカルの制御用ポートに起動ごとの合言葉ファイルで認証する方式は、Jupyter（トークン）や Docker の考え方と同じ種類の一般的な方法で、研究ではない。
