# 読むだけの探索役（`explore`）

- **対象と範囲：** モデルが「どこに何があるか」を別のモデル（探索役）に調べさせる道具 `explore`。探索役は `find` と `read` だけを使い、ファイルのパスと行の範囲を返す。読んだ中身は、頼んだモデルの文脈に入らない。
  - 範囲外：編集を任せること、並行して複数の探索役を動かすこと、探索役同士の会話、ハーネスが自動で探索役を呼ぶこと。
- **関連コード：** `core/src/explore.rs`（道具の定義、探索役の指示と繰り返し）、`core/src/turn.rs`（呼び出しの振り分け、`INOCODE_EXPLORE_MODEL`）、`core/src/agent_tools.rs`（道具の一覧）。
- **根拠の状態：** RESEARCH_SUPPORTED（査読前の研究だけ。弱い）。
  - 読むだけの役に関係する部分だけを返させると、解決率を落とさずに費用が下がった：SWE-Edit（査読前）。
  - 探索役で解決率が上がり、作業役のトークンが減った：FastContext（査読前、**取り下げ済み**のため根拠としては弱い）。
  - 編集まで任せると悪くなった：ChainSWE（査読前）。このため編集は任せない。
  - 研究の詳細と数値（原文で確認）：[colleague-review.md](colleague-review.md) の 5 と 7。
- **ユーザーの判断：** 2026-11-20「同僚は実装前に仕事をサブエージェント投げるのも実装したいが使うべき場面に自動で呼べるようにしたい。逆に使うべき時じゃないなら１人でやってほしい」「根拠あるなら実装していい。ベンチマークは全部終えてからやろう」。

## 研究との対応

| 研究 | 研究の仕組み | inocode との違い |
|---|---|---|
| SWE-Edit, arXiv 2604.26102v2（査読前） | 閲覧役：1 つのファイルと質問を受け、関係する行の範囲を JSON で返す。作業役 GPT-5、閲覧役 GPT-5-mini。SWE-bench Verified 69.9% → 70.3%、費用 −7.7%（表 1） | inocode の探索役は、ファイルを決めずにプロジェクト全体を探す |
| FastContext, arXiv 2606.14066v3（査読前、v4 で取り下げ） | 読むだけ（READ・GLOB・GREP）の探索役が、パスと行の範囲を返す。必要なときに作業役が呼ぶ。Multilingual で 71.7 → 75.0（トークン −22.1%）など（表 1） | 探索役は専用に学習したモデル。inocode は学習していない汎用のモデル（既定は作業役と同じ） |
| ChainSWE, arXiv 2607.02606v2（査読前） | 閲覧と編集を下位の役に任せると、順に直す課題で単独より悪い（3 つ目で 27.7% 対 17.5%） | inocode は編集を任せない |

- 「いつ呼ぶか」：どちらの研究も、作業役のモデルが必要なときに呼ぶ（道具として渡す）。ハーネスが事前に判断する方式を、コーディングで評価した研究は見つからなかった（[colleague-review.md](colleague-review.md) の 5）。inocode も、モデルが道具の説明を読んで呼ぶかを決める。説明には「探すのに何度も検索や読み込みが要るとき」に使い、1 つのファイルや 1 回の検索なら直接 `read`・`find` を使うよう書いた（推測による文面）。

## 実装

- 引数は `question`（何を探すか）だけ。
- 探索役の指示：場所だけを 1 行に 1 つ、`path:first-last` と短い説明で返す。パス・名前・行番号・数値・エラーの文はそのまま写し、コードは引用しない。見つからなければ何を探したかを書く。挨拶・敬語・前置き・締めは書かない（[colleague-review.md](colleague-review.md) の 7、ユーザーの判断）。
- 道具は `find` と `read` だけ。ほかの道具を呼ぶと、実行せずに断る。どちらも読むだけなので、承認のモードによらず人の承認を待たない。その代わり、係は人に聞けないので、次のものは実行せずに断る（ゴールの判定役も同じ）：
  - プロジェクトの必須の規則が止める、または確認を求める呼び出し（`rules-and-local-issues.md`）。
  - プロジェクトのフォルダーとスレッドの場所の外を読む呼び出し（`approval-modes.md` の「プロジェクトの外」）。
- 最大 20 回の要求。20 回目の後は、それまでに見つけた場所で答えるよう求めて、もう 1 回だけ要求する。
- モデル：既定は作業役と同じ。`INOCODE_EXPLORE_MODEL` で、同じ提供元の別のモデルにできる（SWE-Edit は小さいモデルを閲覧役にした）。
- 探索役のトークンは、そのターンの使用量に足す。探索役の会話は保存しない（返した答えだけが履歴に入る）。
- ターンが中断されたら、探索役も止まる。

## 検証

- 結合テスト（`server/tests/turn_tcp.rs` の `explore_answers_with_places_found_by_a_helper_that_only_reads`、模擬 API）：探索役が専用の指示と `find`・`read` だけを渡されること、`find` の結果が探索役に返ること、`write` を断りファイルが作られないこと、探索役の答えが道具の結果になること、探索役が読んだ中身が頼んだモデルの文脈に入らないこと。
- 未検証：実際のモデルが適切な場面で `explore` を呼ぶか、返す場所が正しいか、費用が下がるか。ベンチマークは inocode の完成後に行う（ユーザーの判断、2026-11-20）。
