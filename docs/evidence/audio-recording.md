# 音を録る道具（`audio`）

- **対象と範囲：** 録音できる機器の一覧と、機器を選んで決めた秒数だけ WAV か FLAC に録ること。音の解析はしない（2026-11-24 ユーザーの指示「機器を指定して音を調べる機能はただ指定形式で録音できればいい。解析を実装するな」）。パソコンで鳴っている音を録ることは対象外。
- **関連ソースコード：** `core/src/audio.rs`、`core/src/turn.rs`（`needs`、`approval`：録るときは人の承認を待つ）、`core/src/agent_tools.rs`（登録）。
- **根拠の状態：** UNSUPPORTED_APPROVED。機能の有効性を示す研究は調べていない。ユーザーの承認：「camera以外に録音機能あってもいいかも。もちろん全OS対象」「機器を指定して音を調べる機能はただ指定形式で録音できればいい」（2026-11-24）。

## 作り

- 機器を扱う部品：`cpal` 0.18（Apache-2.0）。Windows は WASAPI、macOS は CoreAudio、Linux は ALSA を使う。Codex の音声部品（`codex-rs/voice-host`）も同じ部品を使っている。
- ファイルを書く部品：WAV は `hound`、FLAC は `flacenc`（ともに Apache-2.0、Rust だけで書かれている）。
- 形式：サンプリング周波数、チャンネル数、ビット数（8／16／24／32、32 ビットの浮動小数点は WAV のみ）。指定しないものは、機器の既定の形式に合わせる。
- 機器がその形式を直接出せないときは、機器の既定の形式で録ってから変換する。
  - 実測（この開発機、Windows）：共有モードの機器は 48kHz か 192kHz しか返さなかった。
  - 周波数を下げるときは、範囲内の平均をとる。上げるときは直線で補う。1 チャンネルにするときは全チャンネルの平均をとる。
  - 簡単な変換なので、周波数を下げると折り返しの雑音が残りうる（推測）。
- 録るときは、モードによらず人の承認を待つ。`auto` モードでも審査役には回さない（`camera` と同じ扱い）。
- Linux でビルドするには ALSA の開発用ファイル（`libasound2-dev`）が要る。CI で入れている。

## テスト

- `audio::tests`
  - WAV が指定した形式になる。
  - FLAC の先頭と STREAMINFO が正しい。
  - 形式の誤りを録る前に断る。
  - 機器の形式を、指定した周波数とチャンネル数に変換できる。
- 機器の一覧（`lists_the_devices_here`、手で実行するもの）：この開発機の Windows で、WASAPI の入力機器が出ることを確かめた。
- 手で動かす試験：`audio::tests::records_here`。`INOCODE_AUDIO_CALL` に道具の引数、`INOCODE_AUDIO_FILE` に書き出す先を入れる。
- 本物での確認（2026-11-24、ユーザーの承認「試す」）
  - 既定のマイク（LifeCam Studio）で 5 秒、16kHz・1 チャンネル・16 ビットを指定した。
  - 機器は 48kHz・2 チャンネル・f32 で録り、指定の形式に変換して WAV に書いた。
  - 読み直すと形式は指定どおり（16000 Hz、1 チャンネル、80,000 サンプル）だった。
  - 音は最大 18／32768 でほぼ無音だった。マイクの音量の問題か、話していなかったのかは確かめていない。
- **未検証：**
  - 声が入った録音で、内容が正しく残るか。
  - macOS と Linux での実機の動き（CI ではビルドとテストだけ）。
